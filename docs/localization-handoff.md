## 4. 原补丁为什么没有生效

原程序启动时查找 `game/patch.pp`，已有分卷展开后的补丁却位于 `game/Data/patch.pp`。缺少前一个文件时，程序跳过补丁，继续使用原日文资源。

v0.1.1 在文件适配层增加了只读路径兼容：根目录没有补丁时回退到 `Data/patch.pp`。候选实现又加入应用包补丁，当前读取优先级为：

1. 应用包内的补全补丁，由 `BIKO3_LOCALIZATION_PATCH` 指定。
2. 用户已有的 `game/patch.pp`。
3. `game/Data/patch.pp`。

该重定向只用于读取及文件状态查询，写入不重定向。相关代码在 `ios/runtime/Biko3FS.c`。

## 5. 汉化方法与思路

### 5.1 先恢复“补丁生效后的资源”

不直接把基础资源中的日文都算成遗漏。先解析原资源，再应用已有中文补丁，得到游戏实际使用的图片和文本，随后检查其中剩余日文。

资源清单已覆盖 23 个 PP 档案、7,285 个条目以及 131 个外置文件。界面档案 `bk3_00.pp` 有 575 个条目，原补丁覆盖其中 80 个。

`tools/biko3_assets.py` 支持两种档案布局：外置 TBL 索引和旧式内置索引。解析时检查记录大小、范围、名称、重复项及文件总长度。原补丁使用 BKPT 格式和压缩数据；工具按实际原文件验证补丁基底，再恢复最终内容。

原中文补丁的 203 个资源条目均已通过基底与格式检查；加上配置条目共 204 个。格式通过不能证明翻译正确或画面正常。

### 5.2 以原补丁为基底添加补全

采用合并补丁，保留已有汉化及原署名，不重新翻译已覆盖内容。每个新增文件绑定：资源身份、补丁生效后的源文件 SHA-256、译图 SHA-256。

合并后比较新旧补丁的所有条目，要求改动集合与本批目标集合完全一致。未经目标清单授权的资源变化会报错。

### 5.3 本地字体重绘

用户已授权使用 Python、Pillow 和中文字体处理图片文字。当前本地使用 `C:/Windows/Fonts/NotoSansSC-VF.ttf`；字体未随工具自动分发，其他机器需自行提供字体。字体文件或 Pillow 版本变化可能影响输出，需重新审查成品哈希与预览。

图片按结构处理：

- 独立文字精灵：重新渲染文字，保留选中、未选中及禁用状态的配色和透明度特征。
- 确认窗口：只重绘明确的文字矩形，保留窗口外形。
- 区域编号：替换文字及该区域的透明度，保留圆角边缘。
- 背景上的文字：记录修改矩形，检查矩形外像素完全不变。
- 带图标的按钮：保留图标，只修改文字区域。

所有成品均检查尺寸；透明度按资源类型核对，不能对全部图片机械地复制原 alpha。

### 5.4 角色姓名保护

已撤回此前生成的 4 张姓名译图。`tools/build_localization_supplement.py` 的 `PRESERVED_NAMES` 拒绝已识别的姓名资源，即使传入旧批次也会报错。

这项检查仅覆盖列出的独立资源。对于姓名与正文共用一张图的角色介绍，仍需人工保护姓名矩形；不能声称一个文件名列表已经自动覆盖所有情况。

## 6. 已解决的问题与教训

### TGA 无法预览

图片查看工具不支持直接打开部分 TGA。解决办法是转成 PNG 再查看，原 TGA 保持不变。`preview_texture()` 会核对像素、尺寸、alpha 和源文件哈希。

此前多次关于图像工具 `sexual` 拒绝及请求 ID 的报告没有可核实的调用记录，已撤回。不能将这些说法作为实际阻碍、验收证据或进度依据。

### TBL 解码曾不完整

最早得到 216 条记录时，存在截断名称和损坏记录；“解码完成”“可无损回写”的早期结论过早。修正回溯复制逻辑并严格检查桶表和记录后，外置索引档案共恢复 4,752 条记录。旧导出目录不能作为可信输入。

### 旧字形透明度残留

区域编号曾在修改 RGB 后恢复原 alpha，导致日文字形轮廓重新出现。修正版重建文字区域的背景透明度，只保护区域外像素；已新增测试验证不复活旧字形。

### 背景插值与旧字阴影

部分按钮有旧字阴影残留，已扩大清理矩形。宣传图片的复杂背景插值曾产生拉伸痕迹，已制作覆盖面板方案，但这些后续图片尚未合入当前 103 张候选，也不能默认通过最终视觉审查。

## 9. 覆盖安装与游戏数据

实现思路是把合并补丁放入应用包的 `dm/localization/patch.pp`。更新 IPA 后，新应用包携带新补丁，Documents 中约 3 GB 的原始 Data 和 `saves` 不需要被修改。

**目前可以确认代码和 macOS 读取路径支持这个方案，但尚不能承诺 iPhone 覆盖安装已通过。** 最终需要使用相同签名账号、应用标识验证覆盖安装，并检查现有资源、存档与新增文字。

若最终验证通过，用户只需更新 IPA，无需重新下载六个资源分卷。若不能通过，发布说明必须具体写清新增文件、放置目录、大小和是否需要重新导入，不能笼统要求重下全部数据。
